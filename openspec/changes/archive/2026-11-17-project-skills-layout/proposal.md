# Proposal

Implements **M4.3 — Fix the project skills' layout** (milestone.md, M4).

## Why

None of the four project skills in `.claude/skills/` loads. Claude Code only loads `.claude/skills/<name>/SKILL.md` with `name` and `description` frontmatter, and ours are flat files (`commit.md`, `test.md`, `reduce-comments.md`, `improve.md`); three have no frontmatter at all. So `/commit` and `/test` don't exist, and the project's commit rules (checks, script file for the hook, no amend, no push) live only in memory notes. ccattler has the same four skills in the working layout and is the template.

## What Changes

- `commit`, `test` and `reduce-comments` move to `.claude/skills/<name>/SKILL.md` with `name` and `description` frontmatter, as in ccattler.
- `commit` states vmherd's commit rules: the checks (gofmt, go vet, golangci-lint, go test, `openspec validate` when `openspec/` changed), staging by name and splitting unrelated work, the message format used in the history (`<what changed> (Mx.y, task n.m)`), the commit run from a script file because the pre-commit hook matches command text, and the never-list (amend, reset, rebase, push, Co-Authored-By, `[skip ci]`, `rm -rf`).
- `test` adds golangci-lint and a compile check of the `integration`-tagged tests, which need libvirt to run.
- `improve` is deleted: it repeats CLAUDE.md, and implementing an item is now the `openspec-apply-change` skill's job (CLAUDE.md workflow item 8). ccattler rewrote its `improve` for its own milestones; vmherd has no use for a second implementation path.
- A new test, `test/tooling/TestProjectSkillsUseSkillLayout`, fails when a skill in `.claude/skills/` is not a `<name>/SKILL.md` with matching `name` and a description, so the layout can't silently break again.

Out of scope: the agents (M4.4), permission rules (M4.5), new skills, and any change to the OpenSpec skills (generated by `openspec update`; the test only checks their layout).

Vagrant has no equivalent: this is developer tooling for working on vmherd, not vmherd behaviour.

## Capabilities

### New Capabilities
None. Developer tooling only, so `.openspec.yaml` sets `skip_specs: true`.

### Modified Capabilities
None.

## Impact

- `.claude/skills/`: `commit/SKILL.md`, `test/SKILL.md`, `reduce-comments/SKILL.md` (moved and rewritten), `improve.md` removed. The `openspec-*` symlinks are unchanged.
- New `test/tooling/skills_test.go` (no build tag; runs in `go test ./...` and CI).
- milestone.md: M4.3 links this change; on completion, ticked with a Result note and the M4 done count.
